### Kernel implementation

`ggml/src/ggml-cuda/fattn-common.cuh:664-703` -- replaced float loop with:

```cpp
const int k_packed = (qbyte & 0x03)
    | (((qbyte >> 2) & 0x03) << 8)
    | (((qbyte >> 4) & 0x03) << 16)
    | (((qbyte >> 6) & 0x03) << 24);

const int    sumi = ggml_cuda_dp4a(k_packed, Q_q8[k_KQ_0/nthreads], 0);
const float2 Q_ds = ((const float2 *) Q_ds_v)[k_KQ_0/nthreads];

sum += scale * (Q_ds.x * sumi + d * Q_ds.y / QI8_1);
```

On gfx906, `ggml_cuda_dp4a` resolves to `__builtin_amdgcn_sdot4(a, b, c, false)`.

### Test 5 validates the /QI8_1 correction

`test_vec_dot_k_dp4a_formula` (test 5): 20 runs, srand(54321), with actual
Q8_1-quantized Q inputs (int8 values + ds.x scale + ds.y sum-of-floats). Validates:
- The integer dot `sumi = sum_b(k2bit[b] * q_int8[b])` (dp4a emulation)
- The zeropoint term `d * Q_ds.y / QI8_1` (where QI8_1=8, one Q8_1 block = 8 dp4a groups)
- Total per-group: `scale * (Q_ds.x * sumi + d * Q_ds.y / QI8_1)`
- All 20 runs pass at relerr < 1e-4.

## What we learned

1. **The /QI8_1 correction is exactly right.** One Q8_1 block (32 elements) spans
   8 dp4a groups. Each group adds `d * Q_ds.y / 8`. Over 8 groups: `d * Q_ds.y`
   total -- the correct zeropoint contribution. Without the /8, you get 8x the
   zeropoint. The test confirmed this numerically.

2. **vec_dot calling convention.** `Q_q8` and `Q_ds_v` are NOT global pointers.
   They are per-thread register arrays. Each warp thread holds its own portion of
   Q (4 int8 per int register, one float2 per Q8_1 block). The index
   `k_KQ_0/nthreads` is the per-thread slot, not a byte offset. The warp then
   reduces partial sums via `warp_reduce_sum` after the loop.

3. **2-bit to int8 lane packing.** The 4 2-bit codes from one byte expand to
   four int8 lanes packed into a 32-bit int:
   `lane[b] = (qbyte >> (b*2)) & 0x03` at byte positions 0, 8, 16, 24.
   Values 0-3 are non-negative, so signed dp4a gives the same result as unsigned.

4. **stride = QK2_KVARN / sizeof(int) = 128/4 = 32.** One KVarN block has 128
   elements, 32 bytes of qs (32 uint8_t), and 32 int-sized groups for dp4a.
   The loop variable `k_KQ` runs over `[0, D/sizeof(int))` and `byte_idx = k_KQ % stride`
   indexes into `qs[]` directly.

5. **Pre-existing RED test in test-q2-kvarn-dequant test 4.** `test_block_size()`
   expects `dequantize_row_q2_kvarn` to assert when called with k=64 (not a
   multiple of 128). The assert does not fire -- the function silently processes
   a partial block. This is a pre-existing failure from the dequant implementation
   sprint (item 09 equivalent), NOT caused by DP4A changes. Left as-is; the
   dequant correctness issue should be filed separately if it matters.

6. **DP4A is not available on the build host if no GPU.** The HIP compiler
   still compiles `ggml_cuda_dp4a` calls -- the intrinsic is always present at
   compile time, guarded by the arch target. Linking `ggml-hip` with gfx906 as
   the target works fine.
